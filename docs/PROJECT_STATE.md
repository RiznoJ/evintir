# Evintir — Project State

Maintained per CLAUDE.md operating notes. Overwrite stale entries, don't append forever.

## Works now that didn't before
- Per-country News tab filtering: `fetch_feeds.py` tags each ingested event with
  `country_tags: []` (COUNTRY_KEYWORDS, word-boundary keyword match on headline).
  `index.html`'s country popup filters `DATA.events` by `country_tags.includes(name)`
  instead of the old coarse `region === matchRegion` match, which collapsed most
  countries into the same "Global" bucket and showed unrelated world news.
- Zero-match state: countries with no tagged coverage show
  "No country-specific coverage in the current window." instead of silently
  falling back to an unfiltered feed.
- All feed-derived text (`e.summary`, `e.source_name`, `e.location`, `e.event_type`,
  `e.why_it_matters`, `e.tags`) is now run through a shared `esc()` HTML-escaper
  before any `innerHTML` insertion. `e.source_url` is additionally validated as
  http(s)-only (`safeUrl()`) before being used as an `<a href>`.

## Files changed
- `scripts/fetch_feeds.py` — added `COUNTRY_KEYWORDS`, `classify_countries()`,
  `country_tags` field on each event.
- `index.html` — hoisted a shared `esc()` + added `safeUrl()`; `countryPopupHtml`
  filters on `country_tags`; escaped remaining unescaped feed-text interpolations
  in `renderMap`, `renderTable`, `renderBrief`.
- `data/events.json` — regenerated by running `python3 scripts/fetch_feeds.py`
  against live feeds (84 events, 27 with ≥1 country tag as of this run).

## Known limitations / unfinished pieces
- Country keyword matching is still headline-only substring/word-boundary
  matching, same crudeness as the existing REGION_RULES — documented, not solved.
- Coat-of-arms badges: verified all 22 tracked countries in `countries.js`
  already have `coatOfArms` entries, including North Korea, South Korea, and
  Japan (Japan correctly labeled via the Imperial Seal file). The handoff
  doc's "Stage 2" task was already complete before this session — no changes
  needed there.
- UI change was verified via `node --check` on the extracted inline script,
  Python JSON parsing, and a Node simulation of the client-side filter logic
  against the real regenerated `events.json` — NOT via an actual browser
  render. No headless-browser tool was available this session; a manual
  `python3 -m http.server` + click-through pass is still worth doing before
  treating this as fully verified in-browser.
